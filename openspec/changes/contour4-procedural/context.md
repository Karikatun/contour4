# Контекст процедурной планировки

21 ноября 2026 года владелец задал направление. Кольцо служит тестовым модулем и может войти в каталог готовых групп. Остальные комнаты нужно процедурно расставлять в разных плоскостях, исключать пересечения интерьеров и квот, давать разные пути для груза и процедурно подбирать пары порталов.

Владелец уточнил правило отображения. По Tab открывается штатный интерфейс с плоской развёрткой. Каждый конец портала выглядит как обычный проём, а общий цвет указывает, с каким проёмом он связан. Две отметки могут находиться в разных местах плана.

Генератор начинается с каталога модулей. Владелец запросил комнаты разных размеров, коридоры, многоэтажные комнаты и составные блоки по принципу кольца, в том числе пары, стыкованные крышами или полами. В каталог также входят коридор с мостом из середины к верхнему стыку и спиральный коридор с выходом, перевёрнутым на 180°. [Каталог модулей](module-catalog.md)

Владелец задал плотную компоновку. Комнаты примыкают друг к другу, а при повороте на 90° сходятся углами в поперечном разрезе. В авторских данных тестового кольца расстояние между маркерами комнат на концах каждого из двух поворотных мостов составляет 7,07 м, или 8,84 м после масштабирования в Unity. Стыки тестового кольца переданы на отдельную доработку. [Расстановка кольца](../../../prototype/assets/layout.json) · [Масштаб импорта](../../../prototype/ring/Editor/BuildRing.cs#L14)

В штатном REPOLib SDK обычные модули состыкованы в горизонтальной сетке через границы X/Z. В прототипе «Контура-4» штатный генератор уже присоединяет готовое вертикальное кольцо к старту Manor. Внутри `RingRuntime` использует имена четырёх комнат и явный список связей, а `RingMap` использует их подготовленную плоскую развёртку. `Crossing` строит преобразование между двумя локальными кадрами проёма. В принципе эти кадры можно передать из сгенерированного плана. [Модули REPOLib](https://repomods.com/apis/repolib/sdk/levels.html#modules) · [Стыковка кольца и список проёмов](../../../prototype/ring/Plugin/RingRuntime.cs#L50) · [Преобразование проёма](../../../prototype/ring/Plugin/Portal.cs#L7)

Проверка ранней схемы прочитала авторский `layout.json`. В исходных двух парах дверей координаты порогов на карте совпали, а нормали направлены навстречу. Перестановка выходов в `Loot3` сохранила размеры 3,6 × 3,2 м и встречные нормали, но дала разрыв 8 м у обеих дверей. Это был конфликт для схемы с общим порогом. С парными цветовыми отметками такой разнос на плане допустим. Из `Loot3` до нижнего отсека насчитано три простых маршрута по графу, два с исключённым верхним проёмом и ноль по одним физическим стыкам. Проезд гружёной тележки по каждому новому маршруту проверяется отдельно. Методика Propose–Probe–Compose применена на данных кольца. [Результат пробы](../../../local-evidence/contour4-procedural/layout-probe.json)

Первая штатная квота размещена внутри `StartRoom`. При проверке раннего кольца уже встречалось пересечение шахты квоты с верхней комнатой. Для второй квоты нужен эксперимент с отдельным `ExtractionPoint` в процедурной сборке. Надо выяснить, на каком этапе генерации игра обнаруживает точку и сколько пространства ей нужно в полном цикле сдачи. Наиболее близкий проверенный контур — сольный прототип R.E.P.O. 0.5.2, REPOLib 4.5.1 и Unity 6000.3.17f1.
